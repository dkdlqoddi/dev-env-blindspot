# AGENTS.md

## What this repo is

This repository contains shared Codex skills and custom-agent profiles. Consumer projects mount it as a git submodule at `.codex/shared`, then run `install.sh`. The installer creates individual relative skill links under `.agents/skills`, copies custom-agent profiles into `.codex/agents`, merges the mandate hook into `.codex/hooks.json`, and maintains a complete fallback mandate block in root `AGENTS.md` and in an existing `AGENTS.override.md`.

The workflow implements Thariq's "Finding Your Unknowns" lifecycle: `requirements-interview` → `blindspot-pass` → `explainer` → `work-report`, orchestrated by `blindspot-flow`.

## Test

Run the repository's standard check from its root:

```bash
bash test/check.sh
```

For browser verification of generated quiz HTML, serve the files through localhost with `python3 -m http.server`; browser automation may reject direct local-file URLs.

## Conventions

- Model-facing instruction files (`SKILL.md`, `agents/*.toml`, and `MANDATE.md`) are English. User-facing deliverables generated by the skills are Korean. Do not mix these purposes.
- Templates under `skills/*/templates/` use Korean for deliverable text and placeholders. Comments addressed to the generating model (`<!-- -->` and `//`) are English. Established cross-referenced identifiers, including lens names, `Human/Agent 섹션` labels, and quadrant terms, stay in English and receive a Korean gloss when first introduced to a reader.
- A skill frontmatter `description` is its trigger condition and always begins with "Use when ...".
- Every `SKILL.md` has a `## Gotchas` section. Add recurring failure modes there; do not delete existing entries or create separate gotcha documents.
- Custom-agent source files are TOML. The `name` field is the agent's stable identity and must match the source filename stem. `change_analyzer`, `codebase_scanner`, `doc_verifier`, and `domain_researcher` are read-only. Only `check_runner` uses `sandbox_mode = "workspace-write"`, because documented checks may create test caches or build artifacts; its instructions still forbid source edits and external side effects.
- Model policy is role-specific. `doc_verifier` and `check_runner` pin `gpt-5.6-terra` at low reasoning effort. `codebase_scanner` and `domain_researcher` pin `gpt-5.6-terra` at medium reasoning effort. `change_analyzer` omits model fields and inherits the parent model.
- Deliverable paths are stable: `docs/blindspot/YYYY-MM-DD-<slug>-{requirements,unknowns,explainer,report}.md`, `docs/blindspot/quiz/*.html`, and `docs/blindspot/<slug>-implementation-notes.md` without a date prefix.
- The non-developer readability rules are intentionally duplicated across four skills for self-containment: `work-report` steps 3–4, `explainer` step 2, `requirements-interview` steps 3–4, and `blindspot-pass` steps 3–5. Update every copy together. The standard covers vocabulary (plain Korean first, term in parentheses; no arrows or code syntax) and sentence shape (one fact per sentence, at most 25 어절; quiz options at most 40 characters; each quiz answerable from its own 변경 요약). The countable subset is enforced by `skills/work-report/scripts/quiz_check.py`.
- The evidence-first Question policy lives once in `MANDATE.md`. Ask only questions whose answers change the design and cannot be resolved from evidence. More than seven queued questions requires more scanning first. Never block implementation on reversible choices: use a conservative default, record it immediately, and batch confirmation at a checkpoint. Ask irreversible or destructive choices immediately. Calibrate how much to ask after each review cycle.
- The perfect-score quiz gate is part of the workflow contract. Do not merge or declare work complete until the user confirms every Pre-Merge Quiz answer is correct.

## Consumer contract (breaking-change checklist)

The installer owns the following names and paths. Renaming, moving, or changing their meaning is a breaking change; update `install.sh`, `test/check.sh`, and `README.md` together.

- Skill identities and source directories: `blindspot-flow`, `blindspot-pass`, `explainer`, `requirements-interview`, and `work-report` under `skills/<name>/`. They install as relative links under `.agents/skills/<name>`.
- Reserved custom-agent identities and source files: `change_analyzer`, `check_runner`, `codebase_scanner`, `doc_verifier`, and `domain_researcher` under `agents/<name>.toml`. They install as real copied files under `.codex/agents/<name>.toml` and replace consumer files with the same reserved names.
- Hook and mandate sources: `hooks/mandate.sh` and `MANDATE.md`. The hook registration installs into `.codex/hooks.json`.
- Fallback marker strings: `<!-- dev-env-blindspot:mandate:start -->` and `<!-- dev-env-blindspot:mandate:end -->`. The installer owns only the block between these markers in `AGENTS.md` and, when that file already exists, `AGENTS.override.md`.
- Consumer mount and managed destinations: `.codex/shared`, `.agents/skills`, `.codex/agents`, `.codex/hooks.json`, `AGENTS.md`, and an existing `AGENTS.override.md`.

## Design docs

Founding and later design/plan records live under `docs/superpowers/specs/` and `docs/superpowers/plans/`; completed implementation reports live under `docs/blindspot/`. Dated design, plan, and report documents are historical records. Do not rewrite them during runtime ports or terminology migrations.
