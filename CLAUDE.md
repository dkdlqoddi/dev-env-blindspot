# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Shared Claude Code skills/agents that other projects consume as a git submodule mounted at `.claude/shared/`, wired up by `install.sh` (individual relative symlinks into `.claude/skills` and `.claude/agents`, a SessionStart hook running `hooks/mandate.sh` plus the session model `"model": "opus"` / `"effortLevel": "xhigh"` merged into the consumer's `.claude/settings.json`, and a `@.claude/shared/MANDATE.md` import in the consumer's CLAUDE.md). It implements Thariq's "Finding Your Unknowns" lifecycle: `requirements-interview` → `blindspot-pass` → `explainer` → `work-report`, orchestrated by `blindspot-flow`. Deliverables are a fixed set of living documents per area — three tiers, `rules.md` / `map.md` / `specs/<unit>.md` — updated in place, never dated per-cycle files.

This branch (`claude-antigravity-cowork`) splits implementation off to Antigravity: Claude Code (Opus at xhigh effort) plans with `swarm-plan` and audits with `swarm-review` / `swarm-auditor`; Antigravity (Gemini 3.8 Flash High only) executes the plan with the `swarm-run` skill — a loop that relays the actions of its `scripts/swarm_next.py` state machine — and the `swarm-worker` / `swarm-checker` subagents shipped under `antigravity/` and linked into the consumer's `.agents/` by `install-antigravity.sh`. The two harnesses share one working tree and talk only through `docs/swarm/`.

## Conventions

- Model-facing instruction files (`SKILL.md`, `agents/*.md`, `MANDATE.md`, `antigravity/**/*.md` frontmatter and bodies): English. User-facing deliverables the skills generate: Korean. Do not mix.
- Templates (`skills/*/templates/*`, `antigravity/skills/*/templates/*`): deliverable text and placeholders Korean; instruction comments addressed to the generating model (`<!-- -->`, `//`) English. Exception: the swarm package templates (`plan.md`, `task.md`, `status.md`, `result.md`) describe technical documents read only by models and developers, so their guidance and free text are English, while their headings, header labels, table headers, and status values stay Korean because the scripts match them. Cross-referenced identifiers (lens names, tier section headings, quadrant terms, 웨이브) keep their established form. Skills locate sections by exact heading text, so template headings are a contract (checked by `test/check.sh`).
- Template ownership: `rules.md` / `map.md` belong to blindspot-pass, `spec.md` to explainer, `notes.md` / `quiz.html` to work-report, `plan.md` / `task.md` to swarm-plan (Claude side), `status.md` / `result.md` to swarm-run (Antigravity side; `status.md` is rendered only by `swarm_next.py`). A skill that needs another skill's template names it by skill ("the `explainer` skill's `templates/spec.md`", installed at `.claude/skills/explainer/templates/spec.md`); templates are never duplicated. Claude-side SKILL.md files refer to Antigravity-side files by their installed path (`.agents/skills/swarm-run/...`), never by `templates/<name>` (check 10 resolves that pattern within each harness's tree).
- Skill frontmatter `description` is the trigger condition — always "Use when ...". Antigravity skills follow the same rule; their `name` is the slash command.
- Every SKILL.md (both harnesses) has a `## Gotchas` section. Append recurring failure points there; never delete entries. When a structural change makes an entry factually wrong, rewrite it to name the new referent — correcting a stale referent is not deletion.
- Model placement is fixed by the user: Claude Code judges on Opus at xhigh effort, Antigravity runs only Gemini 3.8 Flash High, and no medium variant appears anywhere. The Claude Code session gets `"model": "opus"` / `"effortLevel": "xhigh"` from `install.sh` (added to the consumer's `.claude/settings.json` when absent; a value the project already set is kept and noted on stderr). Skills cannot pin a model, so everything else is pinned in agent frontmatter.
- Claude Code agents are read-only by design — they never edit files. Keep `tools` minimal (`Bash` only where git inspection or running the project's standard checks is required, with read-only instructions in the body). Pin `model` in frontmatter: `haiku` for mechanical checkers (doc-verifier, check-runner), `sonnet` for exploration and research (codebase-scanner, domain-researcher) — both to save Claude tokens; change-analyzer and swarm-auditor carry `model: opus` and `effort: xhigh` because their verdicts feed the merge gate and whether subagents inherit the session effort is undocumented (check 2 enforces the pin).
- Antigravity subagents (`antigravity/agents/*.md`) use Antigravity's frontmatter: `subagent: true`, `mainAgent: false`, `commandExecutionPolicy: auto`, `model: inherit`, and an explicit `tools:` block sequence (an empty list means no tools) drawn from the 9-name allowlist in `test/check.sh` check 2b (file, search, run, web tools — a subset of the 17 tool names measured on agy 1.1.27; the 2026-09-08 design doc §7 lists all 17). The agent file's `model:` wins over `invoke_subagent`'s `Model` (measured on agy 1.2.2; `model: flash` ran gemini-3.8-flash-tiered), so every swarm agent inherits and the whole swarm runs on the dispatcher's `--model gemini-3.8-flash-high --effort high` — agy refuses to start when `--effort` contradicts the `-high` variant, and it exposes no variable with the running model, so the command is the only place the model is chosen. Check 2b also requires `commandExecutionPolicy: auto` so headless runs never wait on a prompt. `swarm-worker` is the only agent in the repo that edits files, and only inside its brief's 소유 파일. `swarm-checker` is read-only. The rule file carries `trigger: always_on`.
- `antigravity/skills/swarm-run/scripts/swarm_next.py` holds every execution decision (dispatch set, holds, retries, interrupted-웨이브 recovery, commits, round sync) and is the only writer of `docs/swarm/status.md`; the dispatcher model only relays its `ACTION:` output. On resume it refuses changes outside the swarm's own uncommitted work before it resets any interrupted task's 소유 파일. It imports `swarm_check.py` from the shared checkout, and `test/swarm_scenario.py` pins its behavior — change both together.
- Deliverable path contract baked into skills and MANDATE: `docs/<area>/rules.md` (Tier 1, ≤60 lines), `docs/<area>/map.md` (Tier 2, ≤150), `docs/<area>/specs/<unit>.md` (Tier 3, ≤200), `docs/notes/<slug>.md` (deleted at acceptance), `docs/quiz.html` (overwritten each cycle), `docs/swarm/` (plan package `plan.md` + `tasks/<id>.md` written by swarm-plan, run records `status.md` written by `swarm_next.py` and `results/<id>.md` written by swarm-worker; deleted at acceptance). An area is a directory under `docs/` holding `map.md`; canonical areas are `frontend` and `backend`, a single-area project uses `core`.
- Swarm plan contract (enforced by `skills/swarm-plan/scripts/swarm_check.py`, called by swarm-plan and by `swarm_next.py next` before every run): task ids `T01`…, one brief per id, 웨이브 numbers, no 웨이브 holding more tasks than 동시 실행 상한, 선행 ids in earlier 웨이브 only, one `## 웨이브별 검증` row per 웨이브 (`전체 검증` or one backticked command, the last 웨이브 `전체 검증`), a latest 회차 row whose 범위 is `전체` or table ids, 소유 파일 and 참고 파일 as backticked paths judged against git — never the working tree — so the verdict survives the swarm's own commits: `(신규)` = absent at 기준 커밋 and marked only by the task that creates the path, any other path exists at 기준 커밋 or HEAD or lies under an earlier 웨이브's `(신규)` path; paths match literally first (brackets and spaces are ordinary characters) and as globs only when they do not exist; trailing `/` or a git tree = directory; normalized 소유 파일 disjoint within a 웨이브; no 참고 파일 on another same-웨이브 task's 소유 파일; no 소유 파일 under `docs/swarm/`, `docs/notes/`, `docs/quiz.html`, or an area's tier files; briefs with 목표 / 해야 할 일 / 완료 조건 / 검증, no placeholders, no delegating words (필요하면, 적절히, if needed, as appropriate, …). Workers share the tree (`Workspace: inherit`) — ownership disjointness is the only thing keeping parallel writes safe.
- Readers are separated per section, not per document. Non-developer register (plain Korean first with the term in parentheses; no arrows/code syntax; one fact per sentence, ≤25 어절; quiz options ≤40 chars; quiz answerable from its own 변경 요약): spec 목적과 배경 / 요구사항 / 동작 방식 / 의도적 범위 제외, the 결정 and 질문 cells, map 영역 개요 and 하는 일, rules 규칙 cells, interview and blindspot questions, the whole quiz. Technical register: 근거, 위치, 처리, 기각한 대안, 변경 이력, 리뷰 포인트, and the whole swarm package (English free text; briefs and results are read by developers and models). The standard is intentionally duplicated across 4 skills for self-containment (requirements-interview steps 3–4, blindspot-pass steps 3–5, explainer step 2, work-report report step 4) — edit it in all of them together; swarm skills must not carry the marker. The countable subset is enforced by `skills/work-report/scripts/docs_check.py`.
- Section ownership in a spec: explainer rewrites 목적과 배경 / 동작 방식 / 의도적 범위 제외 (keeping work-report's as-built additions); requirements-interview appends 요구사항 (blindspot-pass may add domain acceptance criteria there); 결정 기록 / 엣지케이스와 제약 are append-only for everyone (rows one line, date first, so `grep -h '^| 20' docs/<area>/specs/*.md` finds past decisions across the area); a 열린 질문 row is removed by the skill that records its answer; whichever skill first writes to a unit creates its spec with every heading and flips the map's 상세 명세 cell; work-report writes 변경 이력 after the quiz passes. Empty sections are not placeholders. Swarm skills never write tier documents; swarm-review writes only `docs/notes/<slug>.md`.
- Question policy (evidence-first asking, 7-question cap that triggers more scanning instead of more asking, no mid-work blocking on reversible decisions, per-cycle calibration) lives once in `MANDATE.md`; `blindspot-pass` step 4 and `work-report` notes/report modes implement the mechanics. Bootstrap (blindspot-pass step 0) decides areas from evidence and asks only when the evidence conflicts. Swarm workers never ask: a brief must pre-decide everything, and an undecidable point is recorded under 막힌 것 and surfaced by swarm-review.

## Consumer contract (breaking-change checklist)

Renaming or moving any of these breaks consumer projects — update `install.sh` / `install-antigravity.sh` + `test/check.sh` + `README.md` together:

- `skills/<name>/` directory names (= installed skill names, referenced in `MANDATE.md`)
- `agents/*.md` filenames (= `subagent_type` values referenced inside SKILL.md files)
- `antigravity/skills/<name>/`, `antigravity/agents/*.md`, `antigravity/rules/*.md` (= names under the consumer's `.agents/`; `swarm-worker` / `swarm-checker` are `TypeName` values printed by `swarm_next.py` and named in `antigravity/skills/swarm-run/SKILL.md`)
- `hooks/mandate.sh`, `MANDATE.md`, `install-antigravity.sh` paths (referenced by consumer `settings.json`, CLAUDE.md import line, README)
- The `model` / `effortLevel` keys `install.sh` writes into the consumer's `.claude/settings.json` (README §1 and §3 tell users to check them)
- Tier paths `docs/<area>/{rules.md,map.md,specs/}`, `docs/notes/`, `docs/quiz.html`, `docs/swarm/{plan.md,tasks/,status.md,results/}` (referenced by MANDATE, every SKILL.md on both sides, README, `docs_check.py`, `swarm_check.py`, `swarm_next.py`)
- `skills/explainer/templates/spec.md` (created by four skills), `skills/work-report/scripts/docs_check.py` (called from four SKILL.md files), `skills/swarm-plan/scripts/swarm_check.py` (called from swarm-plan and imported by `swarm_next.py` from the shared checkout, with `.claude/skills/swarm-plan/scripts/` as the fallback), `antigravity/skills/swarm-run/scripts/swarm_next.py` (run by the Antigravity `swarm-run` skill as `.agents/skills/swarm-run/scripts/swarm_next.py`, the path it also prints into its own follow-up commands), `antigravity/skills/swarm-run/templates/result.md` (named as `.agents/skills/swarm-run/templates/result.md` in the worker prompt `swarm_next.py` prints and in `swarm-worker.md`), `antigravity/skills/swarm-run/templates/status.md` (rendered by `swarm_next.py`; a status.md without the `- 회차:` line is refused as the previous format)
