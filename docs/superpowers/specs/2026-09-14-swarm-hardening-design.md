# 스웜 실행 보강 설계 — 외부 리뷰 반영

- 날짜: 2026-09-14
- 상태: 구현, 오프라인 시나리오 검사, agy 1.2.2 실측(모델 조합, 중단 후 재개), 코드 리뷰와 변경 분석 반영 완료. 머지 전 퀴즈 대기
- 브랜치: `claude-antigravity-cowork`
- 선행 스펙: `2026-09-08-antigravity-swarm-design.md`. 두 하네스 구조, `docs/swarm/` 파일 인터페이스, 3계층 문서 계약은 그대로다. 이 문서가 그 문서의 결정 6·7·9·11, §4 계약 일부, §5 실행 프로토콜, §12 열린 질문을 대체한다
- 입력: Fable 5.1 리뷰(사용자 공유, 2026-09-14). 사용자가 원하는 배치는 계획 Opus 5 xhigh(또는 Fable 5.1), 구현 Gemini 3.8 Flash High, 리뷰·검증 Opus 5이고, 목표는 제한된 Claude 토큰을 효율적으로 쓰는 것이다

## 1. 목적과 배경

2026-09-08 설계는 끊김 없는 스모크 테스트(3작업 2웨이브)를 통과했다. 리뷰는 실제 사이클에서 곧 부딪칠 흐름 — 재개, 재계획, 재시도, 테스트 먼저 웨이브 — 이 막힌다는 점과, 모델 배치가 사용자 의도와 다르다는 점을 지적했다. 지적은 전부 코드와 대조해 사실로 확인했고(1번은 임시 저장소로 재현), 대조하는 동안 리뷰에 없던 결함 네 가지를 더 찾았다. 구현 뒤에는 코드 리뷰와 변경 분석(change-analyzer)이 결함 아홉 가지를 더 찾아 함께 고쳤다(§3).

방향은 한 줄이다. **실행 쪽에 남아 있던 판단을 스크립트로 옮기고, 판정 기준을 작업 트리가 아니라 git에 둔다.** 빠른 모델은 스크립트가 출력한 동작을 옮기기만 한다.

## 3. 리뷰에 없던 결함

구현 전 대조에서 찾은 것:

| 결함 | 영향 | 대응 |
|---|---|---|
| 재시도 후에도 실패한 웨이브의 변경이 커밋되지 않음 | 감사(`git diff 기준 커밋...HEAD`)가 그 변경을 못 봄. 재계획 뒤 `/swarm-run`이 트리 오염으로 멈춤 | `(검증 실패)` 커밋으로 남기고 멈춤 |
| 옛 결과 파일이 새 결과로 읽힘 | 재시도·다음 회차에서 워커가 결과를 안 써도 옛 상태 줄이 완료로 읽힘 | 프롬프트에 시도 번호. 결과의 시도가 다르면 무효. 시도는 회차를 넘어 누적 |
| 선행이 부분 완료인 작업의 규칙 없음 | 파견도 보류도 아닌 상태로 남음 | 선행이 완료가 아니면 보류 |
| `invoke_subagent`가 워커 종료 전에 반환(실측) | 기다리지 않고 수집하면 일하는 워커를 실패로 기록 | `collect`가 wait 액션을 내고, 모두 답했을 때만 `collect --final` |

구현 뒤 코드 리뷰와 변경 분석에서 찾은 것:

| 출처 | 결함 | 수정 |
|---|---|---|
| 코드 리뷰 | 작업 트리 쪽 이름 바꾸기(`git add -N`)의 porcelain에서 원래 경로를 잘못 읽음 | 두 상태 칸 모두 R/C를 확인 |
| 코드 리뷰 | 실패 메시지가 폴더를 가리키면 그 안의 소유 파일과 매칭되지 않음(전체 재시도로 넘어감) | 실패 경로를 폴더일 수 있는 것으로 비교 |
| 변경 분석 | 재개가 스웜 밖 변경 검사보다 먼저 되돌리기를 실행 | 검사 먼저. 실행 중 작업의 소유 파일은 허용 목록에 포함 |
| 변경 분석 | 공백이 든 소유 파일 경로를 조용히 버림, 대괄호 경로(`app/[id]/page.tsx`)를 글롭으로 오판 | 글자 그대로 먼저, 글롭은 그다음(계획 검사와 되돌리기 모두) |
| 변경 분석 | 재시도 파견이 동시 실행 상한을 무시 | 웨이브당 작업 수 ≤ 상한을 검사로 강제(재시도도 상한 안) |
| 변경 분석 | checker 답 판독 불가를 실패로 처리해 재시도 쿼터를 씀 | 실행 불가처럼 멈춤 |
| 변경 분석 | 이전 형식 status.md를 작업 0개로 읽고 엉뚱한 사유로 멈춤 | 이전 형식이라고 알리고 멈춤 |
| 변경 분석 | 실행 불가로 멈출 때 결과 파일이 코드와 다른 커밋으로 갈라짐 | 상태 기록 커밋은 status.md만 |
| 변경 분석 | "(신규)는 만드는 작업에만"이 강제되지 않고, 그 이유를 적은 Gotcha는 git 기준 판정에서 틀림 | 두 번째 (신규)를 거부하고 Gotcha 정정 |

## 4. 확정된 결정사항

| # | 결정 | 선택 | 근거 | 기각한 대안 |
|---|---|---|---|---|
| 1 | 경로 판정 기준 | git(기준 커밋·HEAD). 작업 트리는 보지 않음. 경로는 글자 그대로 먼저, 글롭은 그다음 | 스웜 자신의 커밋이 판정을 바꾸면 재개·재계획이 막힘. HEAD 조건은 세션으로 옮겨 구현한 작업이 만든 파일을 뒤 작업이 가질 수 있게 함 | 기준 커밋만(리뷰 원안) / 디스크 유지 + 재개 때 검사 생략 — 재계획 회차가 여전히 막힘 |
| 2 | 실행 판단의 위치 | Antigravity 쪽 `swarm_next.py`가 status.md를 혼자 쓰고 모든 전이를 결정 | 셀 수 있는 것은 스크립트(저장소 원칙). 표 편집과 재개 계산을 Flash에 맡기지 않음 | 읽기 전용 "다음 할 일" 출력 — 상태 표는 여전히 Flash가 고침 / `swarm_check.py` 하위 명령 — Claude 쪽 스크립트가 Antigravity 쪽 기록을 씀 |
| 3 | 웨이브 검증 | 웨이브마다 계획이 정한 명령, 마지막 웨이브는 전체 검증. 끝낼 때 마지막 기록이 전체 검증 통과가 아니면 최종 검증 1회 | 테스트 먼저 웨이브가 구조적으로 실패하지 않게. 재계획이 앞 웨이브만 다시 돌려도 최신 트리를 보증 | 마지막 웨이브와 swarm-review에서만 전체 검증(리뷰 원안) — 중간 웨이브가 무검증 |
| 4 | 재시도 | 실패 경로 주인만 → 웨이브 전체 1회 → 중단 | 주인만이면 테스트 파일에서 드러난 구현 결함을 못 고침. 항상 전체면 실패 하나에 워커 전원 재파견 | 경로 주인만 1회(리뷰 원안) / 항상 전체 1회(기존) |
| 5 | 실패한 웨이브 | `(검증 실패)` 커밋 후 중단 | 감사가 실패를 보고, 재실행이 트리 오염으로 막히지 않음. 전용 브랜치라 되돌리기는 git revert | 되돌림 — 감사가 원인을 못 봄 / 미커밋 유지 — 재개 규칙이 복잡 |
| 6 | 중단 복구 | 스웜 밖 변경 검사를 통과한 뒤 작업 단위로. 결과(시도 일치)가 있으면 기록, 없으면 소유 파일을 되돌리고 대기 | 한 웨이브의 소유 파일은 겹치지 않아 작업 단위 되돌리기가 안전. 끝난 워커의 작업을 버리지 않음. 스웜 밖 변경이 있으면 아무것도 건드리지 않음 | 웨이브 전체 되돌림(리뷰 원안) / 반쯤 쓴 파일 위에서 이어 하기 / 복구 명령을 사용자가 따로 실행 |
| 7 | 실행 불가 | 검증 명령이 시작하지 못하거나 checker 답에 검증 결과 줄이 없으면 재시도 없이 중단. 웨이브는 커밋하지 않고 status.md만 커밋. 다음 실행은 재파견 없이 검증부터 | 워커가 고칠 수 없는 환경 문제이거나 dispatcher가 답을 잘못 옮긴 것 | 실패처럼 재시도 — 쿼터 낭비 / 판독 불가면 자동 재검증 — 반복되면 끝나지 않음 |
| 8 | 워커 모델 | 워커 `model: inherit` + `--model gemini-3.8-flash-high`, checker `model: flash` | 실측: 에이전트 파일의 model이 호출의 Model보다 우선. inherit만이 `--model`을 워커에 전달 | 파일에 구체 모델 이름 고정 — 버전마다 공유 저장소 수정, 미실측 / `--effort high` — 모델 이름이 더 명시적 |
| 9 | dispatcher 모델 | 워커와 같은 `--model`(High) | 워커를 High로 두는 실측된 경로가 inherit뿐. dispatcher 판단은 스크립트가 대신하고, 늘어나는 것은 Gemini 쿼터 | 리뷰 권고 "오케스트레이터 medium 유지" — 워커 High와 양립하는 실측 경로 없음 |
| 10 | 감사 모델 | swarm-auditor 세션 모델 상속 | Flash의 완료 주장을 diff와 대조하는 유일한 자리. change-analyzer와 같은 논리 | sonnet 유지 — 가장 아끼면 안 되는 자리를 아낌 |
| 11 | 스웜 패키지 언어 | 본문 영어, 헤딩·라벨·상태 값 한국어 | 사용자 선택. 브리프는 강한 모델의 가장 큰 출력, 결과 파일은 감사가 읽음. 라벨은 스크립트 계약 | 한국어 유지(2026-09-08 결정 11) / 브리프·결과만 영어 |
| 12 | 회차 상한 | 한 번 재계획된 작업이 또 실패하면 세션에서 직접 구현하고 계획에서 제거 | 두 번째 실패는 브리프가 아니라 능력 문제. 세 번째 회차는 브리프 재작성·감사 비용만 더함 | 상한 없음(기존) |
| 13 | 워커 안전 | 파괴적 명령·패키지 설치·네트워크·전역 설정 금지(브리프가 원문으로 적은 명령만 예외), 전용 worktree 권장, 예약 경로 검사 | `--dangerously-skip-permissions`와 auto 실행인데 금지 목록이 git뿐이었음 | `--sandbox` 강제 — 테스트·git 동작 미검증 |
| 14 | 회귀 방지 | `test/swarm_scenario.py`가 agy 없이 상태 전이를 흉내, `test/check.sh` 검사 13 | 리뷰 1·2·3번은 끊김 없는 스모크로는 안 잡힘 | agy 스모크에만 의존 — 쿼터·로그인 필요 |
| 15 | 중단 후 재실행 | 기다리는 규칙 없이 바로 재실행 | 실측: CLI가 끝나면 서브에이전트도 멈춤(60초간 변경 없음) | 재실행 전 대기 시간 규칙 |
| 16 | 웨이브 크기 | 웨이브당 작업 수 ≤ 동시 실행 상한을 `swarm_check.py`가 강제 | swarm-plan Bounded 규칙을 검사로. 첫 파견은 상한으로 나누지만 재시도 파견은 대상 전원을 보내므로, 웨이브 크기가 상한 안이어야 재시도도 상한 안 | 재시도 파견을 상한으로 분할 — 실패 메시지를 상태에 따로 보관해야 함 |

## 5. `swarm_next.py` 상태 기계

| 명령 | 언제 | 하는 일 |
|---|---|---|
| `next` | 실행 시작·재개 | `swarm_check.py` 검사, 새 회차 반영, 스웜 밖 변경 거부, 중단 복구, 다음 액션 출력 |
| `collect [--final]` | 파견한 워커가 모두 답한 뒤 | 결과 파일의 상태·시도 기록. 없으면 wait, `--final`이면 실패(결과 없음) |
| `verified` | checker가 답한 뒤(답을 표준 입력으로) | 검증 기록 후 커밋·재시도·중단 중 하나 |

| 액션 | dispatcher가 할 일 |
|---|---|
| `dispatch` | 출력된 JSON 그대로 `invoke_subagent` 한 번, 모두 답하면 `collect` |
| `verify` | checker 한 항목 호출, 답을 heredoc으로 `verified`에 |
| `wait` | 아직 답하지 않은 워커를 기다렸다가 `collect`, 모두 답했으면 `collect --final` |
| `finish` / `stop` | 출력된 한국어 요약을 그대로 사용자에게 |

전이 규칙:

- 작업: 대기 → 실행 중 → 완료 / 부분 완료 / 실패. 선행이 완료가 아니면 보류. 시도는 파견마다 1 증가하고 회차를 넘어 누적. 회차 칸은 마지막으로 돈 회차.
- 웨이브 완료: 모든 작업이 끝 상태이고, 마지막으로 작업이 돈 회차 이후의 마지막 검증 기록이 통과(모두 보류면 건너뜀).
- 검증 실패: 이번 회차 첫 실패는 실패 메시지 경로의 주인이 일부면 그 작업만(`실패 — 일부 재시도`), 아니면 전원(`실패 — 전체 재시도`). 일부 재시도 뒤 실패는 전체 재시도. 그 밖은 `실패 — 중단`, `(검증 실패)` 커밋, 끝남.
- 실행 불가: 검증 명령이 시작하지 못했거나 checker 답에 `검증 결과:` 줄이 없음. 기록하고 웨이브 커밋 없이 끝남(status.md만 커밋). 다음 실행은 검증부터.
- 종료: 모든 웨이브 완료 후 마지막 검증 기록이 전체 검증 통과면 끝. 아니면 `최종` 검증.
- 재개: 먼저 트리 변경이 `docs/swarm/`과 아직 커밋되지 않은 작업(실행 중 포함)의 소유 파일 안에만 있는지 확인하고, 아니면 멈춤. 통과하면 실행 중 작업은 결과(시도 일치)가 있으면 기록, 없으면 소유 파일 되돌림(글자 그대로 먼저)·결과 삭제·대기.
- 새 회차(plan.md 회차 번호가 status.md보다 큼): 범위의 id와 보류 작업만 대기로. 실행 중 작업이 남은 채 회차가 늘었거나, 같은 회차인데 작업 표가 다르거나, status.md가 이전 형식이면 멈춤.

## 6. 계획 패키지 계약 변경

- `plan.md`: `## 웨이브별 검증`(`| 웨이브 | 검증 | 이유 |`) 추가. 웨이브당 작업 수 ≤ 동시 실행 상한. 기준 커밋은 재계획 회차에서도 바꾸지 않는다. 회차 범위는 재계획한 id만 적는다.
- `tasks/<id>.md`: (신규)는 만드는 작업의 브리프에만(두 번째 표시는 거부). 참고 파일은 같은 웨이브 다른 작업의 소유 파일이면 안 된다. 검증은 그 작업만 끝나면 통과하는 명령. 공백·대괄호가 든 경로는 글자 그대로 쓴다.
- `status.md`: `swarm_next.py`만 쓴다. 머리글에 회차, 작업 표에 회차 칸, 웨이브 검증 표에 회차 칸과 결과 값(통과 / 건너뜀 / 실행 불가 / 실패 — 일부 재시도 / 실패 — 전체 재시도 / 실패 — 중단), 웨이브 칸의 `최종`.
- `results/<id>.md`: 시도는 프롬프트의 시도 번호. 본문 영어.
- 금지어에 영어 추가: if needed, as needed, if necessary, as necessary, as appropriate, where appropriate, appropriately.
- 예약 경로: `docs/swarm/`, `docs/notes/`, `docs/quiz.html`, 영역의 `rules.md`·`map.md`·`specs/`는 소유 파일이 될 수 없다.

## 10. 의도적 범위 제외

- 에이전트 파일에 구체 모델 이름(gemini-3.8-flash-high)을 쓰는 방식은 실측하지 않았다. dispatcher만 medium으로 내리는 구성에는 그 실측이 필요하다.
- `--sandbox` 모드에서 테스트와 git이 도는지는 확인하지 않았다. 전용 worktree 권장으로 대신한다.
- 재시도 라우팅은 실패 메시지에 나온 경로만 본다. 스택 트레이스 해석이나 import 관계 분석은 하지 않는다.
- 이미 커밋된 실패 웨이브를 자동으로 되돌리지 않는다. 재계획 회차가 판단한다.
- 이전 형식 status.md를 새 형식으로 바꿔 주지 않는다. 소비 프로젝트에서 진행 중인 스웜이 아직 없다.
- Antigravity 앱 화면에서의 동작은 여전히 검증하지 않았다.
