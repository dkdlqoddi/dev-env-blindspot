## 2026-07-29 15:44 — 관리 입력과 예약 경로의 허용 범위를 엄격히 제한

- 보수적 선택 여부: 예, 모호하거나 지원하지 않는 입력은 변경 전에 중단한다.

## 2026-07-29 16:31 — Codex 발견 검사에 제한적 호환 fallback 적용

- 결정: 발견 검사는 먼저 `--strict-config`를 사용하고, 현재 `debug` 하위 명령이 해당 플래그를 지원하지 않는다는 정확한 오류에만 플래그 없는 재실행을 허용한다.
- 이유: Codex CLI 0.146.0은 전역 옵션을 노출하지만 `debug prompt-input`에서는 이를 거부하며, 플래그 없는 동일 격리 검사는 mandate와 다섯 스킬을 정상 발견한다.
- 검토한 대안: 현재 CLI에서 항상 실패하는 원래 명령을 유지하거나, 엄격 모드 시도 없이 플래그를 완전히 제거하는 방식.
- 보수적 선택 여부: 예, 엄격 모드를 우선 유지하고 알려진 비호환 오류에만 fallback 범위를 제한했다.
- 계획과의 이탈: 있음. 계획의 단일 정확 명령을 사용자 승인 하에 호환성 있는 2단계 실행으로 바꾼다.
- 사용자 확인 필요: 아니오. 2026-07-29 사용자가 fallback 적용을 승인했다.

## 2026-07-29 17:08 — 최종 동등성 리뷰의 런타임 공백 보완

- 사용자 확인 필요: 아니오. Task 6은 동등성 리뷰의 Critical/Important 공백을 수정하도록 승인된 범위다.

## 2026-07-29 17:51 — report-mode 추가 위험의 두 번째 수정 wave 보류

- 결정: 단일 역할 단계의 부모 fallback·mandate 예외와 관리 루트 symlink 경계를 추가 수정할지 사용자 확인 전에는 보고서·퀴즈 handoff를 진행하지 않는다.
- 이유: 첫 항목은 멀티 에이전트가 완전히 꺼진 환경에서 필수 조사·검증을 중단시킬 수 있고, 둘째 항목은 소비 프로젝트 밖 경로를 따라 쓸 수 있다.
- 검토한 대안: 두 위험을 보고서의 범위 제외로만 남기거나, SDD의 단일 최종 수정 wave 한도를 자동으로 넘겨 즉시 수정하는 방식.
- 보수적 선택 여부: 예, 알려진 동등성·쓰기 경계 위험을 숨긴 채 완료 단계로 넘기지 않는다.
- 계획과의 이탈: 있음. 최종 scoped re-review 뒤 report-mode 분석에서 발견된 추가 위험이라 계획된 한 번의 fix wave 밖이다.
- 사용자 확인 필요: 예. 추가 수정 wave에서 두 위험을 보완하고 다시 검증·리뷰할지 확인한다.

- 이유: 넓은 예외는 일시적 thread 제한에서도 즉시 부모 수행을 허용하며, 기존 공통 문구 검사는 역할·입력 변경과 필수 위임 약화를 놓쳤다.
- 검토한 대안: Skill의 상세 순서만 신뢰하거나, 공통 fallback 문구 존재 검사만 유지하는 방식.
- 보수적 선택 여부: 예, 부모 fallback은 최후 수단으로만 허용하고 각 단계의 의미 계약을 별도로 검사한다.
