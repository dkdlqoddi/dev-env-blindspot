## 목적과 배경

이 단위는 구현 작업을 두 도구에 나누어 맡기는 장치입니다. 생각이 필요한 일은 Claude Code의 강한 모델이 한 번에 합니다. 정해진 대로 고치는 일은 Antigravity의 빠른 모델 여러 개가 동시에 합니다. 두 도구는 같은 폴더의 파일로만 대화합니다. 예전에는 강한 모델 하나가 구현까지 한 줄씩 순서대로 했습니다.

## 요구사항

1. 전체 전략은 Claude Code에서 강한 모델이 세우고 결과를 파일로 남긴다. (사용자 요청 2026-09-08)
2. Antigravity에서는 빠른 모델이 계획 문서를 읽고 작업마다 하위 에이전트를 많이 만들어 동시에 실행한다. (사용자 요청 2026-09-08)
3. Claude Code용 스킬·에이전트와 Antigravity용 스킬·에이전트를 따로 만든다. (사용자 요청 2026-09-08)
4. 작업은 main이 아닌 새 브랜치에서 하고, 의도를 README에 적는다. (사용자 요청 2026-09-08)
5. 기존 다섯 스킬과 다섯 에이전트의 이름과 수는 바꾸지 않는다. (규칙 3, 소비자 계약)

## 동작 방식

설계가 끝난 명세를 바탕으로 계획 스킬(swarm-plan)이 작업을 잘게 나눕니다. 작업마다 브리프 한 장이 생깁니다. 브리프에는 고칠 파일, 할 일, 끝났다고 볼 조건, 검사 명령이 전부 적힙니다. 동시에 도는 작업들은 서로 다른 파일만 고칩니다. 검사 스크립트가 이것을 실행 전에 확인합니다. 사용자가 Antigravity에서 실행 명령을 내리면 실행 스킬(swarm-run)이 계획 문서의 작업 표를 읽습니다. 한 묶음(웨이브)의 작업을 한 번에 여러 하위 에이전트에게 나눠 줍니다. 각 하위 에이전트는 자기 브리프만 읽고 일을 마친 뒤 결과 파일을 씁니다. 묶음이 끝나면 검사 에이전트가 전체 검사를 돌리고 실패한 것만 알립니다. 실패하면 한 번 다시 시도합니다. 그래도 실패하면 거기서 멈춥니다. 묶음마다 변경이 커밋으로 남습니다. 끝나면 Claude Code의 검토 스킬(swarm-review)이 결과를 실제 변경과 대조합니다. 하위 에이전트가 내린 선택은 작업 노트로 옮겨집니다. 문제가 있으면 그 작업만 다시 계획합니다. 문제가 없으면 기존 보고 스킬과 머지 전 퀴즈로 넘어갑니다.

## 의도적 범위 제외

- 인터뷰, 사각지대 점검, 설계 스킬은 Antigravity로 옮기지 않는다. 판단은 Claude Code에 남긴다.
- 하위 에이전트끼리 메시지를 주고받지 않는다. 함께 쓰는 이름은 브리프에 원문으로 적는다.
- 작업별로 모델을 고르는 기능은 없다. 필요해지면 브리프 머리글 한 줄로 더할 수 있다.
- 실패한 묶음을 자동으로 다시 계획하지 않는다. 사람이 본 뒤 계획 스킬이 한다.
- Antigravity 앱 화면에서의 동작은 검증하지 않았다. 명령줄 도구(agy)만 실측했다.
