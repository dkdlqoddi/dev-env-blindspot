## 목적과 배경

이 단위는 구현 작업을 두 도구에 나누어 맡기는 장치입니다. 생각이 필요한 일은 Claude Code의 강한 모델이 한 번에 합니다. 정해진 대로 고치는 일은 Antigravity의 빠른 모델 여러 개가 동시에 합니다. 두 도구는 같은 폴더의 파일로만 대화합니다. 예전에는 강한 모델 하나가 구현까지 한 줄씩 순서대로 했습니다.

2026-09-14 외부 리뷰가 두 가지를 지적했습니다. 끊긴 실행을 이어 가거나 다시 계획한 뒤 실행하는 흐름이 막혀 있었습니다. 구현과 검토에 쓰이는 모델도 사용자의 의도와 달랐습니다. 그래서 실행 중에 필요한 판단을 빠른 모델에게서 떼어 정해진 규칙대로 도는 상태 스크립트로 옮겼습니다. 빠른 모델은 이제 스크립트가 알려 주는 일을 그대로 옮기기만 합니다.

2. Antigravity에서는 빠른 모델이 계획 문서를 읽고 작업마다 하위 에이전트를 많이 만들어 동시에 실행한다. (사용자 요청 2026-09-08)
3. Claude Code용 스킬·에이전트와 Antigravity용 스킬·에이전트를 따로 만든다. (사용자 요청 2026-09-08)
4. 작업은 main이 아닌 새 브랜치에서 하고, 의도를 README에 적는다. (사용자 요청 2026-09-08)
5. 기존 다섯 스킬과 다섯 에이전트의 이름과 수는 바꾸지 않는다. (규칙 3, 소비자 계약)
6. 계획과 리뷰·검증은 Claude Code의 강한 모델이 맡고, 구현은 Antigravity의 Gemini 3.8 Flash High가 맡는다. (사용자 요청 2026-09-14)

9. 스웜 계획·지시서·결과의 본문은 영어로 쓴다. (사용자 선택 2026-09-14)

## 동작 방식

설계가 끝난 명세를 바탕으로 계획 스킬(swarm-plan)이 작업을 잘게 나눕니다. 작업마다 지시서(브리프) 한 장이 생깁니다. 지시서에는 고칠 파일, 할 일, 끝났다고 볼 조건, 검사 명령이 전부 적힙니다. 지시서 본문은 영어로 쓰고, 제목과 항목 이름만 한국어로 둡니다. 동시에 도는 작업들은 서로 다른 파일만 고칩니다. 한 묶음(웨이브)에 넣는 작업 수에는 상한이 있습니다. 묶음마다 그 시점에 통과해야 할 검사 명령도 정합니다. 마지막 묶음의 검사는 항상 전체 검사입니다. 검사 스크립트는 이 규칙들을 실행 전과 재개할 때마다 변경 기록(git 커밋) 기준으로 확인합니다.

사용자가 Antigravity에서 실행 명령을 내리면 실행 스킬(swarm-run)이 상태 스크립트(swarm_next.py)를 부릅니다. 다음에 할 일은 스크립트가 하나씩 정하고, 빠른 모델은 그 출력을 그대로 옮기기만 합니다. 한 묶음의 작업은 한 번에 여러 하위 에이전트에게 나눠 줍니다. 구현 하위 에이전트는 실행 명령에서 고른 모델로 돕니다. 각 하위 에이전트는 자기 지시서만 읽고 일을 마친 뒤 결과 파일을 씁니다. 결과 파일은 이번 시도 번호가 적혀 있어야 인정됩니다. 앞 작업이 완전히 끝나지 않았으면 그 뒤 작업은 보류합니다. 묶음이 끝나면 검사 에이전트가 그 묶음의 검사를 돌리고 실패한 것만 알립니다. 통과하면 그 묶음의 변경이 커밋으로 남습니다. 실패하면 실패한 파일을 맡은 작업만 다시 보냅니다. 그래도 실패하면 묶음 전체를 한 번 더 보냅니다. 그래도 실패하면 그 묶음을 실패 표시와 함께 커밋하고 멈춥니다. 검사 명령이 아예 실행되지 않거나 검사 결과를 읽지 못하면 재시도 없이 바로 멈춥니다. 모든 묶음이 끝났는데 마지막 기록이 전체 검사 통과가 아니면 전체 검사를 한 번 더 돌립니다.

실행이 중간에 끊겨도 같은 명령을 다시 내리면 이어서 합니다. 스웜이 맡지 않은 파일이 바뀌어 있으면 아무것도 건드리지 않고 멈춥니다. 끝난 작업은 살리고, 끝나지 않은 작업은 맡은 파일을 마지막 커밋 상태로 되돌려 다시 보냅니다. 그 파일을 사람이 고쳐 두었다면 그 변경도 함께 되돌려집니다.

모든 묶음이 끝나면 Claude Code의 검토 스킬(swarm-review)이 결과를 실제 변경과 대조합니다. 대조는 세션의 강한 모델을 그대로 쓰는 감사 에이전트가 맡습니다. 하위 에이전트가 내린 선택은 작업 노트로 옮겨집니다. 문제가 있으면 그 작업만 다시 계획합니다. 한 번 다시 계획했는데도 또 실패한 작업은 스웜에서 빼고 Claude Code가 직접 구현합니다. 문제가 없으면 기존 보고 스킬과 머지 전 퀴즈로 넘어갑니다.

## 의도적 범위 제외

- 인터뷰, 사각지대 점검, 설계 스킬은 Antigravity로 옮기지 않는다. 판단은 Claude Code에 남긴다.
- 하위 에이전트끼리 메시지를 주고받지 않는다. 함께 쓰는 이름은 브리프에 원문으로 적는다.
- 작업별로 모델을 고르는 기능은 없다. 호출 때 넘기는 값보다 에이전트 파일의 모델 설정이 우선하므로, 필요해지면 모델별 워커 파일을 따로 두어야 한다.
- 실패한 묶음을 자동으로 다시 계획하지 않는다. 사람이 본 뒤 계획 스킬이 한다.
- Antigravity 앱 화면에서의 동작은 검증하지 않았다. 명령줄 도구(agy)만 실측했다.
- 에이전트 파일에 구체적인 모델 이름을 적는 방식은 실측하지 않았다. 그래서 실행 담당만 한 단계 낮은 모델로 돌리는 구성은 없다.
- 제한 모드(--sandbox)에서 검사와 커밋이 도는지는 확인하지 않았다. 대신 전용 작업 폴더(worktree)를 권한다.
- 다시 보낼 작업은 실패 메시지에 나온 파일 이름으로만 고른다. 오류 추적 내용은 해석하지 않는다.
- 커밋된 실패 묶음을 자동으로 되돌리지 않는다. 다시 계획할 때 사람이 판단한다.
