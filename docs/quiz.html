머지 전 퀴즈: 스웜 실행 보강 (외부 리뷰 반영)

대상: docs/core/specs/swarm-handoff.md · 기준: 278b3b6 (claude-antigravity-cowork)

변경 요약

이번 변경은 외부 리뷰가 찾은 스웜 실행의 결함을 고칩니다. 끊긴 실행을 이어 가지 못하거나, 다시 계획한 뒤 실행이 막히는 문제가 있었습니다. 이제 실행 중의 판단은 빠른 모델이 아니라 상태 스크립트가 합니다. 빠른 모델은 스크립트가 알려 준 일을 그대로 옮기기만 합니다.

실행이 시간 제한 등으로 중간에 끊겨도 같은 실행 명령을 다시 내리면 됩니다. 결과를 남기고 끝난 작업은 그대로 살립니다. 결과 없이 끊긴 작업은 맡은 파일을 마지막 커밋 상태로 되돌린 뒤 다시 보냅니다. 그 파일을 사람이 고쳐 두었다면 그 변경도 함께 사라집니다. 스웜이 맡지 않은 파일이 바뀌어 있으면 아무것도 건드리지 않고 멈춥니다. 계획을 새로 세울 필요는 없습니다.

계획은 작업 묶음(웨이브)마다 그 시점에 통과해야 할 검사를 따로 정합니다. 구현보다 테스트를 먼저 쓰는 묶음은 가벼운 검사를 씁니다. 그 시점에는 전체 검사가 통과할 수 없기 때문입니다. 마지막 묶음은 항상 전체 검사를 통과해야 합니다.

묶음의 검사가 실패하면 실패 메시지에 나온 파일을 맡은 작업만 먼저 다시 보냅니다. 그래도 실패하면 묶음의 작업 전체를 한 번 더 보냅니다. 그래도 실패하면 멈추고, 그 묶음의 변경은 실패 표시와 함께 커밋으로 남깁니다. 검토할 때 무엇이 잘못됐는지 보이게 하려는 것입니다.

구현을 맡는 하위 에이전트는 이제 실행 명령에서 고른 모델을 그대로 씁니다. 전에는 설정 파일에 적힌 가벼운 모델이 우선해서, 높은 등급을 골라도 그 모델로 돌지 않았습니다. 결과를 실제 변경과 대조하는 감사 에이전트도 이제 Claude Code 세션의 강한 모델을 씁니다.

한 번 다시 계획한 작업이 또 실패하면 스웜에서 빼고 Claude Code가 직접 구현합니다. 세 번째 시도는 같은 실패에 비용만 더 들기 때문입니다. 지시서 본문은 강한 모델의 사용량을 줄이려고 영어로 씁니다. 하위 에이전트는 테스트를 약하게 만들거나 지울 수 없고, 설치와 네트워크 명령도 쓸 수 없습니다.
